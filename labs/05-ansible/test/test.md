# Тест до ЛР5 (Studease)

5 питань, 3 хвилини. Платформа показує 0/5: викладач попереджав, що так і має бути.
Питання 3–4 – з теоретичної частини методички, 1, 2, 5 – з прикладів виконання
(inventory, handler, перевірка `ping`).

## 1. Для чого потрібен inventory у показаній конфігурації Ansible?

- **A. Для опису керованих вузлів, груп і параметрів підключення до них.** ✔
- B. Для шифрування playbook.
- C. Для керування flow table OpenFlow.
- D. Для збереження дампів tcpdump.
- E. Для визначення OID у SNMP.

Відповідь: **A**. У лабі: `server1 ansible_host=10.10.0.3` – ім'я вузла й адреса для SSH.
Шифрування playbook – ansible-vault.

## 2. Яку дію виконує handler Restart Network Service у наведеному прикладі?

- A. Створює MIB для SNMP.
- **B. Перезапускає мережевий сервіс після змін конфігурації.** ✔
- C. Змінює транспортний протокол SSH на UDP.
- D. Сканує відкриті порти.
- E. Створює нову групу inventory.

Відповідь: **B**. Handler запускається через `notify` лише тоді, коли задача щось змінила
(оновлено `/etc/network/interfaces` → `systemctl restart networking`).

## 3. Яке призначення Ansible згідно з матеріалом? (кілька варіантів)

- **A. Автоматизація розгортання програмного забезпечення.** ✔
- **B. Автоматизація управління конфігураціями.** ✔
- C. Аналіз лише Ethernet-кадрів.
- **D. Оркестрація серверів.** ✔
- E. Заміна IP-протоколу транспортним протоколом.

Відповідь: **A, B, D**. Методичка: «інструмент для автоматизації управління
конфігураціями, розгортанням програмного забезпечення та оркестрацією серверів».

## 4. Що означає декларативний підхід Ansible, описаний у матеріалі?

- A. Декларативний підхід означає відсутність конфігураційних файлів.
- B. Кожна команда обов'язково вводиться вручну на кожному вузлі.
- C. Ansible працює лише як інтерактивний термінал.
- D. Playbook містить тільки результати моніторингу, а не бажану конфігурацію.
- **E. Конфігурація описує бажаний стан системи, а Ansible застосовує її до інфраструктури.** ✔

Відповідь: **E**. Методичка: «декларативних конфігураційних файлів, які описують бажаний
стан системи … Ansible потім бере ці playbooks і застосовує їх до інфраструктури».

## 5. У прикладі перевірка Ansible завершується UNREACHABLE через помилку SSH-аутентифікації. Що це демонструє?

- A. Inventory автоматично створює SSH-ключ на віддаленому вузлі.
- **B. Наявність вузла в inventory сама по собі не гарантує успішного керування без робочої аутентифікації.** ✔
- C. Модуль ping завжди працює без мережевого з'єднання.
- D. UNREACHABLE означає успішну зміну конфігурації.
- E. Ansible не використовує SSH.

Відповідь: **B**. Ansible ходить на вузли по SSH (методичка: агентів не потрібно,
комунікація через SSH). Без скопійованого ключа (`ssh-copy-id`) чи правильного пароля
вузол UNREACHABLE, хоч і є в inventory.
